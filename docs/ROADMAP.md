# Ren AI HUB – дорожная карта реализации v1.1

**Дата:** 11.11.2026 · **Статус:** рабочий план, упорядоченный по результатам.  
[Спецификация](PRODUCT_SPEC.md) · [Архитектура](ARCHITECTURE.md) · [Решения](DECISIONS.md) · [Текущий статус](STATUS.md)

## 0. Общие правила выполнения

- **Очередность:** P0 → P1 → P2 → P3. Ускорение возможно только без пропуска критических проверок.
- Модуль считается завершённым после работающего артефакта и записанного доказательства приёмки.
- Планируем маленькие шаги, которые дают новую проверяемую возможность.
- Если обнаружена непредвиденная архитектурная проблема, фиксируем её и выбираем минимальное исправление.
- В main размещается только согласованная, проверенная документация и разрешённые к публикации материалы. Изменения кода желательно делать в отдельных ветках, с проверкой и запросом на объединение.
- Не вводить цены, новые платные подключения, публикацию для внешних пользователей и действия с реальными персональными данными без отдельного разрешения.
- Сроки и трудоёмкость оценить после аудита P0, чтобы не обещать неподтверждённые даты.

## P0 – законная и воспроизводимая техническая основа

**Результат фазы:** понятно, какие компоненты можно использовать, что безопасно переносить, как воспроизвести локальный запуск. Облако и подписки не нужны.

| ID | Задача | Артефакт | Приёмка |
|---|---|---|---|
| P0.1 | Раздельно проверить право на изучение, локальное использование/модификацию и коммерческое распространение исходников, зависимостей и графики | Реестр происхождения и условий без приватной переписки в публичном GitHub | Для разрешённых частей понятны условия; неопределённые части не импортируются публично и не используются для коммерческого продукта |
| P0.2 | Инвентаризировать архив и устранить риск публикации секретов/чужих данных/исполняемых файлов | Список включаемых модулей, исключений и отчёт проверки | Отдельно проверены конфигурации, ключи, логотипы, старые EXE, лицензии зависимостей |
| P0.3 | Провести технический и безопасностный аудит архитектуры, доступа к файлам и обновлений | Матрица рисков P0 и решения «сохранить/переделать» по модулям | Критичные риски классифицированы, владельцы и критерии исправления понятны |
| P0.4 | Проверить локальный запуск разрешённой основы; при отсутствии прав – отдельный независимый минимальный прототип | Инструкция запуска, список требований к среде и тестовые данные | Чистый повторный старт, проверка сохранения и тестовый запрос с заглушкой ИИ без внешних расходов; проверка API health только если API используется |
| P0.5 | Зафиксировать базовые проверки и договориться о следующем модуле | Smoke-тесты, журнал фактических результатов, статус v0.x | Повторяемое выполнение и отдельный список неработающих/непроверенных функций |

**Мини-спецификация первой задачи (P0.1–P0.3):**
- **Вход:** архив исходников, публичный RenAIHUB с документацией v1.1, требования владельца.
- **Границы:** осмотр, правообладание, реестр компонентов, безопасность. Никаких публикаций стороннего кода, запусков старых EXE, расходов или подключений реальных ключей.
- **Действия:** определить происхождение → проверить юридические ограничения → ревизия файлов и зависимостей → статический анализ опасных операций → подготовить безопасный план импорта.
- **Проверки:** реестр составлен, риски и запреты явно отмечены, открытый репозиторий чист.
- **Откат:** любые рабочие копии остаются локальными/изолированными до разрешения публикации.

**Gate P0:** разрешённое использование выбранных компонентов **либо независимый собственный прототип**, рабочий локальный запуск без платных вызовов, отсутствие неконтролируемых критичных рисков, зафиксированные результаты тестов. Наличие права на коммерческую дистрибуцию остаётся обязательным условием только для последующей продажи этих компонентов.

## P1 – рабочий инструмент для владельца

**Результат фазы:** работающий личный HUB (диалоги, доступные модели, проекты, история, базовые файлы) и измеренная польза выбранного собственного сценария. Расчёты и коммерческие предложения – только если их выбрали по результатам P0/P1. Внешних клиентов нет.

| ID | Модуль | Проверяемый результат | Условия готовности |
|---|---|---|---|
| P1.1 | Минимальное личное пространство | Один интерфейс; проекты, история, диалоги, доступные модели и настройки | Создать проект, провести безопасный тестовый диалог, сохранить и открыть историю без технических команд |
| P1.2 | Личная работа с файлами | Добавить безопасный тестовый файл, получить и проверить результат его обработки | Проверена область доступа; 3–5 эталонных документов обработаны без утечек и скрытых действий |
| P1.3 | Один выбранный прикладной сценарий | Выбрать по реальным задачам и реализовать минимальный рабочий результат; коммерческое предложение – кандидат | Сценарий подтверждён владельцем; итог проверяем и редактируем; для расчётов используются сверенные формулы |
| P1.4 | Базовая защита и контроль стоимости – до реальных файлов/ключей | Границы файловых операций, безопасное хранение ключей, подтверждение записи, минимальный учёт/лимит расходов | Негативные тесты доступа и записи, отсутствие секретов в логах, проверена остановка по лимиту |
| P1.5 | Проверка собственной пользы | 3 пробные задачи для уточнения порогов, затем протокол 10 безопасных реальных/обезличенных задач | Время, ошибки, стоимость и удобство измерены; решение о развитии принято по уточнённым критериям |

**Gate P1:** продукт приносит измеримую пользу; слабые места известны и не скрыты; стабильность и безопасная обработка данных приемлемы для следующего этапа.

При провале проверки пользы – исправить P1 или сузить сценарий. Не начинать перенос в облако только ради «готовности продавать».

**Результат фазы:** безопасная изоляция компаний и воспроизводимый облачный запуск.

| ID | Модуль | Проверяемый результат |
|---|---|---|
| P2.1 | Организации и серверные права | Обязательная проверка прав в API, БД и файловом хранилище; negative cross-tenant tests |
| P2.2 | Пользователи и сессии | Подтверждение почты, восстановление доступа, безопасная сессия, отзыв доступа |
| P2.3 | Облачная инфраструктура | HTTPS, домен, БД, файловое хранилище, резервирование, мониторинг |
| P2.4 | Администрирование и бюджеты | Панель ролей, лимитов, расходов, журналов и блокировки доступа |
| P2.5 | Правовые и эксплуатационные требования | Проверены условия обработки данных, политика, договоры, сроки хранения и поддержка |
| P2.6 | Пилотные пользователи | Реальные отзывы по согласованным сценариям, показатели ошибок и затрат |

**Gate P2:** изоляция компаний доказана тестами, из резервной копии можно восстановиться, известны цена обслуживания и реакции пилотов; есть решение о платной версии.

**Gate P3:** есть безопасный работоспособный платный сценарий, измеряемая экономика, подтверждённый спрос, договорная и эксплуатационная готовность.

## 1. Зависимости

P0.1 (права) → использование соответствующих компонентов и их публичный перенос; если права недоступны – независимый собственный прототип без копирования кода.  
P0.2 + P0.3 (ревизия) → P0.4 (безопасный локальный запуск разрешённой реализации).  
P0.4 + P0.5 → P1.1 → **P1.4** (защита и лимиты) → P1.2 (настоящие файлы) → выбор P1.3 → P1.5.  
До P1.4 использовать только тестовые данные, заглушку ИИ и не подключать реальные секреты.  
P1.5 (полезность) → P2; P2.1 + P2.2 + P2.3 + P2.5 → P2.6; P2.6 → P3.

## 2. Формат мини-спецификации для каждой задачи

Перед исполнением заполнять в описании задачи или PR:

- **Цель и результат:** какую новую возможность получим.
- **Границы:** что не меняем и какие расходы/публикации исключены.
- **Источники:** исходная версия, документы/примеры, связанные задачи.
- **Реализация:** файлы/модули, зависимости, миграции, шаги.
- **Приёмка:** 2–5 воспроизводимых проверок, включая негативный сценарий.
- **Откат:** как вернуть исходное состояние и сохранить данные.
- **Итог:** что подтверждено тестами, что остаётся неизвестным, следующий шаг.
