# Ren AI HUB – P0.4: динамический стенд WIN01

**Дата:** 11.11.2026 · **Статус:** **частичная динамическая приёмка**. AnythingLLM проверен на синтетических данных через штатные HTTP-маршруты; LibreChat и исходный Tauri/HUB не собраны и не запущены.

**Основание:** [сравнительный протокол](P0_COMPARATIVE_EXPERIMENT_2026-11-11.md), [аудит исходного ZIP](P0_SOURCE_AUDIT_2026-11-11.md), [Issue №2](https://github.com/Ren472230/RenAIHUB/issues/2). Фактические операции проведены через подключённый Desktop Commander на WIN01. Данные приватных программ и сторонний исходный код в публичный GitHub не копировались.

## 1. Исходная среда и ограничения

| Параметр | Подтверждено |
|---|---|
| Система | WIN01 / Windows, Docker Desktop 29.5.3 с Linux-контейнерами |
| CPU/RAM | Docker: 12 CPU, 15,6 ГБ выделенной памяти; Windows: 31,9 ГБ ОЗУ, 15,1 ГБ свободно до теста |
| Место до теста | C: 19,2 ГБ; D: 249,8 ГБ |
| Место после теста | C: 15,37 ГБ; D: 249,81 ГБ (с округлением) |
| Tauri/Rust | `cargo`, `rustc` и стандартные пути Rust на WIN01 не найдены |
| ZIP исходной системы | ZIP доступен в изолированной среде анализа, но не обнаружен на WIN01 в проверенных типовых каталогах; сторонний архив в публичный GitHub не загружали |
| Уже работающие службы | Отдельные контейнеры n8n, Docmost, PostgreSQL и Redis; не останавливались и не конфигурировались |

**Важно:** изменение свободного места C: примерно на 3,8 ГБ за период нельзя считать точным размером установки AnythingLLM: в это время могли изменяться кэши и данные других процессов. Размер самого образа, полученный через `docker image inspect`, – **1 128 335 302 байта** (≈1,05 ГиБ); тестовый том данных находится на D:.

## 2. Что реально запускали

- **Образ:** `mintplexlabs/anythingllm:1.19.0`; локальный ID `sha256:daf5a6ae9d363ed578e7d41e2d0668c7eaa604bd90b0ff27435f893b0906833e`. `docker pull --platform linux/amd64` завершился успешно за **144,83 с**.
- **Контейнер:** `renhub-p04-anythingllm-20261111`, исключительно для QA.
- **Сеть:** `renhub-p04-20261111-internal`, `Internal=true`; опубликован только адрес `127.0.0.1:13001:3001`. Запрос с самого Windows на этот порт **не удался**, поэтому пользовательский браузер не проверялся. HTTP-запросы **внутри** контейнера работали.
- **Границы ресурсов:** `--cpus 2 --memory 2500m --pids-limit 128 --cap-drop ALL --security-opt no-new-privileges`, `Privileged=false`.
- **Хранилище:** только синтетические тестовые данные в `D:\RenAIHUB\P0QA\anythingllm\storage`; проект и история сохранялись между перезапусками.
- **Локальная модель-заглушка:** `renhub-p04-mock-20261111`, образ Node, отдельный внутренний HTTP-сервер с OpenAI-совместимым ответом `RENHUB_P04_MOCK_OK`. Без реальных ключей, API, платных провайдеров и загрузки моделей. Скрипт расположен только в локальном каталоге QA на D:, не добавлен в публичный репозиторий.
- **После теста:** остановлены **только** два P0.4 QA-контейнера, тестовые данные и образы сохранены для повторного испытания. `docker stop` завершил их со статусом `Exited (137)`; корректность graceful shutdown не подтверждена. Остальные сервисы продолжили работу.

## 5. Решение и остаточные риски

**C можно считать подтверждённым работоспособным кандидатом для серверной части личного HUB в изоляции.** Это не подтверждение полной готовности продукта, безопасной работы с клиентскими файлами или годности к коммерческому SaaS.

**A и B не исключены** из сравнения: для них нет сопоставимых динамических измерений. Основная архитектура Ren AI HUB **не изменена**.

Для следующей итерации:
1. Подготовить безопасную копию разрешённых исходников A для сборки на изолированной машине; определить Rust/Tauri и оценить необходимость установки инструментов. Не трогать существующие приложения WIN01.
2. Для C обеспечить проверяемый localhost-доступ из браузера без открытого сетевого выхода и проверить тестовый документ/отрицательные сценарии. Не включать расширенные Linux capabilities без отдельного аудита.
3. B запускать только после оценки свободного места, обособления ресурсов и состава шести служб; заранее зафиксировать образы/digest.
4. Повторно сравнить A/B/C по реальному времени настройки, CPU/RAM, UX, обслуживанию и условиям лицензий; затем принять архитектурное решение.

**Границы:** никаких расходов на ИИ, рабочих документов, секретов, изменений main-кода, перезапусков других приложений или публичной публикации корпоративного архива.
