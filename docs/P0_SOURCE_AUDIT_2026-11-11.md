# Ren AI HUB – P0: статический аудит переданного архива

**Дата:** 11.11.2026 · **Источник требований:** [PRODUCT_SPEC v1.1](PRODUCT_SPEC.md), [ARCHITECTURE v1.1](ARCHITECTURE.md), [ROADMAP v1.1](ROADMAP.md) · **Задача:** [Issue #1](https://github.com/Ren472230/RenAIHUB/issues/1)

**Режим проверки:** чтение ZIP и выборочный статический анализ исходников. Чужой код, установщики, логотипы, содержимое закрытых документов, ключи и сам архив в публичный репозиторий **не добавлялись**. Запуск/сборка/проверка сети и лицензий всех зависимостей не проводились.

## 1. Идентификация и область проверки

- Источник: архив, предоставленный владельцем проекта в разговоре; в публичном репозитории отсутствует.
- ZIP: **211 записей**, **5 962 012 байт**, суммарный распакованный размер **7 700 327 байт**.
- SHA-256: `6e8fd091dd13f204c8ceafa16d489e35ea7dd1efdbae0a8dfd4523a487dc820d`.
- Проверка ZIP: архив читается, небезопасных путей `../` и символических ссылок по метаданным не обнаружено. Пути внутри ZIP используют обратную косую черту.
- Выполнен осмотр оглавления, конфигураций, маршрутов API, аутентификации, прав доступа, инструментов desktop-агента, механизма обновления, сетевого клиента, схемы БД, сценариев сборки и имеющейся документации.
- Файлы обычных лицензий `LICENSE`/`LICENCE`/`COPYING`/`NOTICE` отсутствуют; в архиве есть только `.env.example` среди файлов семейства `.env`. По ограниченному сканированию типовых присваиваний **не выявлены уверенно распознаваемые встроенные секреты** – это не доказательство их отсутствия.
- Файлов с типовыми именами автоматических тестов не обнаружено. В API-компоненте команда lint не проверяет код. Это ограничивает уверенность в работоспособности и безопасности.

**Внутренние ссылки ниже указывают на пути исходного архива для локальной сверки. Исходный код публично не размещён.**

## 2. Реестр компонентов и решение по переиспользованию

| Компонент | Наблюдения | Предварительное решение | Условие |
|---|---|---|---|
| `apps/desktop` – Tauri/React | Есть экран работы с диалогами, проектами, файлами, агентом и изображениями; Windows-установщики в архиве устаревшие | **Кандидат для единственного интерфейса P1** | Права, ограничение файловых возможностей и отключение небезопасного обновления; запуск только после тестов |
| `apps/api` – Fastify | Существуют JWT-вход, пароли с хешированием, проверка активного пользователя, admin-защита, проекты, чаты, модели | **Сохранить после проверки** | Права, сетевые настройки, удаление небезопасного TLS и интеграционные тесты |
| `packages/db` – Prisma/PostgreSQL | Схема и миграции для личных пользователей, проектов, диалогов, ключей провайдеров, логов | **Сохранить при совместимости с P1** | Права, тест миграции/резервного восстановления; для P2 потребуется модель организаций |
| `apps/admin` – Next.js | Есть управление провайдерами, моделями и пользователями; это административный интерфейс | **Оставить существующим вспомогательным инструментом** | Не строить вторую пользовательскую оболочку в P1; проверить минимальный путь настройки |
| `packages/shared` | Есть Zod-контракты и типы | **Повторно использовать условно** | Проверить права, совместимость с действующими API |
| `docker-compose.yml` / Nginx / backup | Конфигурация локального развёртывания и копий данных | **Локальная диагностическая основа** | Перед запуском закрыть доступ извне и изолировать тестовые данные |
| Три `.exe`, графика, служебные документы, `tsbuildinfo` | Содержат старую айдентику, историю и потенциально приватные материалы | **Исключить из импорта и запуска** | Отдельная проверка происхождения/права; воспроизводимая сборка вместо старых бинарников |

**Результат:** полная перепись архитектуры сейчас не обоснована. Минимальный кандидат при подтверждённых правах – уже существующий desktop + локальный API + PostgreSQL, без нового браузерного пользовательского клиента, облака, рассылок и подписок.

## 3. Приоритетные риски безопасности

Оценки основаны на чтении кода; наличие эксплуатируемой уязвимости и её последствия при реальном развёртывании отдельно не проверялись.

| ID | Приоритет | Наблюдение и локальный источник | Исправление до соответствующего использования |
|---|---|---|---|
| S-01 | **Блокирующий для файлов агента** | В `apps/desktop/src-tauri/capabilities/default.json` разрешена файловая область `**`; `apps/desktop/src/agent-tools.ts` проверяет путь преимущественно строково, без доказанной канонической изоляции | Ограничить разрешённую область, проверять реальные пути/ссылки, тестировать попытки выхода из папки |
| S-02 | **Блокирующий для записи** | `apps/desktop/src/App.tsx` вызывает файловые инструменты из ответа модели; `agent-tools.ts` выполняет запись без отдельного подтверждения операции | В P1 разрешить чтение в ограниченной папке; запись – после показа изменений и явного согласия пользователя |
| S-03 | **Блокирующий для обновлений** | `apps/desktop/src/update.ts` загружает исполняемый файл по данным манифеста; `apps/desktop/src-tauri/src/lib.rs` может запустить установщик. Проверка подписи/хеша перед запуском не выявлена | Отключить автообновление и команду запуска установщика до появления проверяемой схемы подписанных обновлений |
| S-04 | **Высокий для внешнего API** | `apps/api/src/lib/proxy.ts` включает режим `rejectUnauthorized: false`; сетевой путь используется для отдельного провайдера | Убрать отключение проверки сертификатов, настроить доверенную цепочку и негативный тест |
| S-05 | **Высокий при расширении сети** | В `apps/desktop/src-tauri/tauri.conf.json` выключена CSP; токен desktop хранится в `localStorage`; `apps/api/src/server.ts` включает отражение Origin в CORS | До выхода за пределы localhost – модель угроз, ограничение источников, политика содержимого, безопасные сессии |
| S-06 | **Средний/высокий при локальном запуске** | `docker-compose.yml` публикует веб-порт без явной привязки к `127.0.0.1`; существуют офисный IP-список и обработка proxy-заголовков | Для P0.4 слушать только loopback; проверить Nginx/IP-политику и отсутствие внешнего доступа |
| S-07 | **Средний по расходам** | `apps/api/src/services/quota.ts` ограничивает токены на основе уже записанного потребления; полного денежного бюджета/предварительного резервирования нет | В P1 измерять стоимость, задать ограничение вызовов и запрет реальных запросов до настройки ключей/лимитов |
| S-08 | **Блокирующий только для P2** | В `packages/db/prisma/schema.prisma` нет модели организаций и связанной изоляции; регистрация не подтверждает email | До внешних клиентов – отдельные организации, роли, права в API/данных, подтверждение почты и тесты пересечений |

**Найденные базовые защитные механизмы:** bcrypt-хеширование паролей, проверка активного пользователя и роли ADMIN, привязка запросов к проектам пользователя, шифрование ключей провайдеров, ограничения запросов и токенов. Их наличие в исходниках **не подтверждает** фактическую защищённость развернутой системы.

## 4. Права и происхождение

| Объект | Что проверено | Статус и действие |
|---|---|---|
| Переданный ZIP/история передачи | Есть файл-передача и описание очищенных настроек, но нет лицензии/договора и доказательства полномочий передающей стороны | **Право коммерческого использования НЕ ПОДТВЕРЖДЕНО**; установить правообладателя и состав прав |
| Исходный код и дизайн старого проекта | В архиве остаются исторические названия сборок/графика/контекстные документы | Не публиковать и не продавать до подтверждения прав |
| Зависимости npm/Rust и включённые библиотеки | Есть манифесты и lock-файлы | Полный реестр лицензий третьих лиц и условий распространения ещё не составлен |
| Документы контекста и пользовательские данные | В архиве имеются служебные и контекстные Markdown-файлы | Не переносить публично; проверить разрешение на использование данных |
| Независимый код будущего Ren AI HUB | Может быть создан с нуля по собственной спецификации | Допустимый резервный путь без копирования исходников, логотипов и закрытых текстов |

**Какие подтверждения нужны:** кто обладает исключительными правами; вправе ли передающая сторона выдавать разрешение; какие права передаются (изучение, локальное использование, изменение, публичный GitHub, распространение, SaaS/подписка); какие элементы исключены; условия третьих лиц. Документы о правах сохранять отдельно от публичного GitHub.

## 5. Выбранный минимальный путь к личному HUB

**Рекомендация: путь А – условное безопасное переиспользование существующего desktop + API + БД.** Основание – уже есть нужные личные функции, и их повторная реализация увеличит объём работ. **Условие: сначала подтверждение применимых прав и устранение блокирующих рисков.** Не создавать новую пользовательскую веб-панель, облачную базу, биллинг или почтовую регистрацию.

**Резервный путь Б:** если права не подтверждены или исправление этих модулей неоправданно, сделать **независимый однопользовательский локальный прототип** по [спецификации](PRODUCT_SPEC.md), без копирования закрытого кода и айдентики. Технологии выбирать после короткого самостоятельного прототипирования.

### P0.4 – мини-спецификация изолированного запуска (пока НЕ выполнено)

1. **Вход и границы:** только разрешённые исходники или собственная реализация; отдельная тестовая копия; никакого запуска архивных EXE и реальных ключей, внешних данных или платных API.
2. **Минимальная конфигурация:** одна клиентская оболочка, локальный API/БД при переиспользовании; веб-доступ только с loopback; тестовые учётные данные; отключены обновления и запись агентом.
3. **Диагностика:** проверить подготовку окружения, миграции, health, вход, список моделей, создание проекта, локальное сохранение/повторное открытие, диалог через заглушку модели.
4. **Негативные сценарии:** внешний сетевой доступ закрыт, попытки записи/выхода из папки запрещены, чужие/просроченные сессии отвергаются, заглушка не вызывает внешний API.
5. **Доказательства:** команды и версии, журнал проверок, скриншот при наличии интерфейса, список известных ошибок, список устранённых рисков, следующий шаг.
6. **Откат:** остановить изолированную копию и удалить только созданные тестовые ресурсы после отдельного контроля их принадлежности.

**В P1:** после успешного P0.4 добавить ограниченные реальные документы, защищённые ключи, учёт расходов и 1 собственный выбранный сценарий. Облако – только после измерения личной пользы.
