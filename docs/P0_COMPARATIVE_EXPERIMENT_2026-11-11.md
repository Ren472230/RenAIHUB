## 4. Итог сравнения без подмены фактов оценками

**Что можно заключить сейчас:**

1. **Быстрее всего получить готовый демонстрационный личный инструмент, вероятно, позволит C – AnythingLLM**: один контейнер, локальное хранение, готовая работа с документами. Это **гипотеза по документации**, измерения времени установки ещё не проводились.
2. **Для сохранения собственных разработок первоочередным кандидатом остаётся A**, потому что исходники уже содержат нужные маршруты и интерфейс. Но он имеет доказанные статические риски и ограничение по правам; без исправлений/согласования переносить код в публичный проект нельзя.
3. **B – LibreChat** функционально многообещающий для многопользовательского продукта, но требует как минимум шесть сервисов в стандартном Compose и замены схемы хранения, если переходить с PostgreSQL-основы.
4. **Нельзя утверждать**, что A, B или C быстрее именно по времени настройки на WIN01, экономичнее при поддержке или пригоднее по UX. Сборки, нагрузка, удобство и реальная стоимость сопровождения **не измерялись**.

**Решение эксперимента:** архитектуру Ren AI HUB **пока не менять**. Для P0.4 использовать два параллельных варианта в изолированной среде: **C как быстрый эталон личного UX** и **A как путь сохранения исходных функций при подтверждённых правах**. LibreChat остаётся резервом для проверки, если A потребует слишком много исправлений, а C окажется трудно адаптировать.

**Не утверждать альтернативный стек только по популярности или лицензии.**

## 5. Протокол полноценного повторяемого испытания P0.4 (не выполнен)

Потребуется изолированный хост с Docker, локальным хранилищем и ресурсами. Для A дополнительно – возможность собрать Tauri на поддерживаемой ОС с Rust/toolchain; для B/C – проверенные и закреплённые образы. Установку ПО на чужой/рабочий компьютер и расходы согласовывать отдельно.

**Одинаковые синтетические задания:**
- Создать проект «Демо», выполнить диалог с локальным модельным имитатором, проверить сохранение и повторное открытие.
- Добавить искусственный документ с двумя пунктами технического задания; получить краткое извлечение и источник каждого пункта.
- Проверить, что агент не может записывать за пределами специально выделенной папки или выполнять незапрошенные действия.
- Показать историю, настройки модели, расход/ограничения; убрать все настоящие API-ключи.
- Измерить активное время от чистой установки до первого сохранённого диалога, потребление RAM/диска, количество необходимых сервисов, ручных действий и обновлений.

| Gate | A | B | C | Критерий |
|---|---|---|---|---|
| E-01 Сборка/установка без реальных ключей | Ожидает | Ожидает | Ожидает | Старт из чистой среды с зафиксированными версиями |
| E-02 UI, проект, чат, история | Ожидает | Ожидает | Ожидает | Один и тот же сценарий с записью результата |
| E-03 Тестовый документ | Ожидает | Ожидает | Ожидает | Сверяемые поля и отсутствие утечки |
| E-04 Границы действий и сети | Ожидает | Ожидает | Ожидает | Нет внешних соединений и лишних файловых прав |
| E-05 Стоимость сопровождения | Ожидает | Ожидает | Ожидает | Измерены RAM/диск, обновление, восстановление и количество компонентов |

**Правило выбора:** допускать только варианты, прошедшие E-01–E-04 без блокирующих рисков; из них выбирать меньшую трудоёмкость первого полезного сценария и сопровождения. Не использовать выдуманные баллы и минуты.
