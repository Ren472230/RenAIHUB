# Ren AI HUB – исследование готовых GitHub-компонентов

**Проверка источников:** 11.11.2026 · **Основа:** [PRODUCT_SPEC v1.1](PRODUCT_SPEC.md), [ARCHITECTURE v1.1](ARCHITECTURE.md), [P0-аудит](P0_SOURCE_AUDIT_2026-11-11.md) · **Статус:** исследование и рекомендации, без установки, копирования чужого кода, релиза и коммерческих обязательств.

## 1. Вывод

**Рекомендуемый путь:** сравнить существующий Tauri/React + Fastify + PostgreSQL с двумя полноценными альтернативами, а затем точечно применять разрешённые библиотеки. Не переписывать всё до проверки воспроизводимого локального запуска.

- **Первый кандидат на интеграцию при сохранении текущей основы:** [Vercel AI SDK](https://github.com/vercel/ai) (единый доступ к моделям, Apache-2.0) и, если существующего UI недостаточно, [assistant-ui](https://github.com/assistant-ui/assistant-ui) (React-компоненты диалога, MIT).
- **Быстрый эталон личного инструмента:** [AnythingLLM](https://github.com/Mintplex-Labs/anything-llm) (MIT для основного проекта; лицензирование отдельно поддерживаемой desktop-оболочки перепроверить перед копированием/распространением).
- **Возможная полная альтернатива исходному коду:** [LibreChat](https://github.com/danny-avila/LibreChat) (MIT), если исправление существующей основы окажется сложнее адаптации новой платформы.

**Значимый компромисс:** в исходном архиве уже есть React 19, Node.js >=22, Fastify 5, Tauri 2, Prisma/PostgreSQL, а также `mammoth` и `pdfjs-dist` для документов. Замена стека ради новой библиотеки должна быть обоснована проверками. Успешный код из GitHub не гарантирует безопасный продукт.

## 4. Сравнение способов создания Ren AI HUB

### A – сохранить имеющуюся базу и заменить проблемные модули (**проверить первым**)

**Состав:** один существующий Tauri/React-клиент, Fastify, PostgreSQL; тестовая модель-заглушка, затем AI SDK для провайдеров, assistant-ui только при подтверждённой необходимости; базовая защита файлов/ключей.

**Плюсы:** минимальная миграция данных, сохранение заложенных функций, общее направление к облаку; возможно проверить локальную ценность раньше проектирования SaaS.

**Риски:** права на корпоративные наработки ещё не прояснены, необходимы исправления из [аудита S-01–S-08](P0_SOURCE_AUDIT_2026-11-11.md), реальная сборка и тесты не проводились.

**Тест:** запустить разрешённую копию в изоляции без внешних ключей и старых EXE, проверить запуск, диалог с заглушкой, проект, историю и блокировку файловой записи. Если не удаётся получить безопасный воспроизводимый минимум, оценить альтернативу B.

### B – использовать LibreChat как новую MIT-основу (**резерв**)

**Плюсы:** готовые чат, модели, агенты, пользователи, административные функции и актуальные механизмы безопасности. Собственные бизнес-шаблоны можно добавлять позднее.

**Риски:** несколько сервисов и MongoDB вместо существующего PostgreSQL; доработка бизнес-логики и Tauri-интеграции; необходимость обновления upstream и отдельной модели организаций.

**Тест:** отдельный локальный стенд на синтетических данных, без интеграции с основным репозиторием. Оценить время и сложность добавления одного пользовательского сценария.

### C – использовать AnythingLLM как готовый личный инструмент (**эталон/быстрый обходной вариант**)

**Плюсы:** локальные модели, документы, память и агенты; можно сравнить с ним ожидаемый пользовательский путь и быстроту получения результата.

**Риски:** собственная структура приложения; импорт в текущий код дороже, чем интеграция нескольких библиотек. Для white-label исходников/десктопной оболочки требуется проверка точного состава и прав.

**Тест:** локальный показ на тестовых документах, без переноса чужих/клиентских данных.

## 5. Порядок действий без затрат

| Шаг | Результат | Обязательная проверка |
|---|---|---|
| 1. Зафиксировать границы прав на корпоративный архив | Понятно, что можно изучать/изменять/продавать; выбран допустимый источник кода | При необходимости краткое подтверждение от уполномоченного правообладателя, без публикации переписки |
| 2. Провести безопасный P0.4 на текущей основе (или выбрать независимую реализацию) | Локальные UI/хранилище/заглушка модели реально работают | Повторная сборка/запуск, нет реальных ключей, записи агента и открытых сетевых портов |
| 3. Отдельно проверить API AI SDK с мок-моделью в TypeScript | Понятна стоимость интеграции и совместимость с Fastify | Тест потока, отмены, ошибок и отсутствия сетевых/платных запросов |
| 4. Сравнить существующий React-чат с assistant-ui | Решение «сохранить свой UI / подключить библиотеку» | Один пользовательский диалог, потоковый ответ, ошибка и история |
| 5. Сравнить готовые AnythingLLM и LibreChat | Понятна ценность полного форка относительно модульной доработки | Одинаковый пробный сценарий, усилия настройки/обслуживания и возможности изменения |
| 6. Проверить документный сценарий | Понятно, достаточно ли уже имеющихся библиотек | PDF и DOCX, включая таблицы; Docling лишь если выявлены конкретные ошибки |
| 7. Принять архитектурное решение | Один выбранный путь, исключённые альтернативы и реальные испытания | Обновить [DECISIONS.md](DECISIONS.md) после проверки, без голословного принятия гипотез |

**Критерий сравнения вариантов:** скорость достижения одного полезного сценария; число новых сервисов; безопасность; условия использования/коммерциализации; нагрузка на одного администратора; возможность будущего облачного разделения организаций.

## 6. Права на исходные наработки – узкая развилка

Отсутствие патента и регистрации программы не отменяет авторское право; оно возникает автоматически ([ГК РФ, ст. 1259](https://www.consultant.ru/document/cons_doc_LAW_64629/be05678dc42ddc67aae5be9ba9beebd367fb9a3f/)). Если код создавался в рамках трудовых обязанностей, исключительное право по общему правилу принадлежит работодателю, если договором не установлено иное ([ст. 1295](https://www.consultant.ru/document/cons_doc_LAW_64629/b131343c6f094841b1ed8c5e6db72a390ea3e11c/)). Факт передачи ZIP не устанавливает объём переданных прав. Не блокировать на этом исследование альтернатив, собственное проектирование и локальные испытания допустимого кода.

Перед коммерческим распространением корпоративных исходников: установить правообладателя, его полномочия и объём разрешений. До этого закрытая реализация остаётся вне публичного репозитория. MIT/Apache-2.0 альтернативы можно оценивать независимо, с соблюдением условий их лицензий.
