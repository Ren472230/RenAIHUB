# Ren AI HUB – журнал решений v1.1

**Дата начала:** 11.11.2026. Этот документ различает утверждённые цели, принятые ограничения, проектные рекомендации и открытые вопросы.

| ID | Статус | Решение / вопрос | Основание и последствия |
|---|---|---|---|
| D-001 | **УТВЕРЖДЕНО владельцем** | Развиваем личный полезный инструмент → проверяем эффект → масштабируем до продукта для малого и среднего бизнеса. | Прямое поручение владельца от 11.11.2026. Успех измеряется на реальных задачах. |
| D-002 | **УТВЕРЖДЕНО владельцем** | Главный репозиторий проекта – Ren472230/RenAIHUB. Рабочая спецификация составляет фундамент. | Прямое поручение от 11.11.2026; спецификация v1.0 зафиксирована в docs. |
| D-003 | **РАБОЧЕЕ ОГРАНИЧЕНИЕ** | Публичный GitHub пока содержит авторскую проектную документацию; сторонний архив кода, EXE и графику не публикуем до проверки прав и безопасности. | Лицензия и право коммерческого использования переданных источников не подтверждены. |

| D-005 | **РАБОЧЕЕ НАПРАВЛЕНИЕ** | Для P1 выбираем один минимальный клиент по результатам P0; переносимую бизнес-логику сохраняем по возможности. Серверные контракты – ориентир для P2. | Не навязывать браузер, desktop, API и PostgreSQL одновременно до проверки их необходимости. |

| D-007 | **РАБОЧЕЕ ОГРАНИЧЕНИЕ** | Сначала локальная версия; почта для публичной авторизации, облачные ресурсы и платежи вводятся на P2–P3. | Контроль затрат и приоритет демонстрации пользы. |
| D-008 | **ГИПОТЕЗА для P3** | Подписки с ограничениями потребления; внедрение, сопровождение и обучение – дополнительные услуги. | Спрос, тарифы, себестоимость и готовность платить пока не подтверждены. |
| D-009 | **ОТКРЫТО** | Коммерческие и лицензионные права на переданную кодовую базу, изображения, установщики и третьесторонние зависимости. | Блокирует публикацию и коммерческую дистрибуцию этих компонентов. |
| D-010 | **ОТКРЫТО** | Окончательная архитектура UI и размещения данных после проверки исходного кода. | Не обещать облачную готовность до тестов. |
| D-011 | **ОТКРЫТО** | Юрисдикция обслуживания клиентов, договоры, обработка данных, налоги, платежный провайдер и роль партнёра по продажам. | Решается до внешних пилотов/продаж; не домысливать условия. |
| D-012 | **ГИПОТЕЗА для P1** | Первичные ориентиры полезности: медианная экономия от 30%, 0 критических ошибок, 7/10 успешных задач; перед итоговым тестом пересмотреть после 3 пробных задач. | Это предложенные пороги, без подтверждения рынком и обязательства достичь их любой ценой. |
| D-013 | **РАБОЧЕЕ ОГРАНИЧЕНИЕ** | При неподтверждённых правах на исходники допускается независимый собственный прототип без копирования чужого кода; импорт/коммерческое использование исходников блокируется. | Права на анализ, использование, изменение и распространение рассматриваются раздельно, результат проверки фиксируется в P0. |
| D-014 | **РАБОЧЕЕ ОГРАНИЧЕНИЕ** | Файловые ограничения, защита секретов и контроль расходов проверяются до обработки настоящих документов и подключений реальных ключей (P1.4 до P1.2). | Устраняет опасную зависимость прежней дорожной карты. |
| D-015 | **РЕКОМЕНДОВАНО** | На P0.4 сначала тестовая заглушка ИИ, без платных запросов; полноценные платные модели только после контроля ключей и лимитов. | Делает техническую проверку воспроизводимой без расходов. |
| D-016 | **РЕКОМЕНДОВАНО – условно** | Минимальный личный HUB: один существующий desktop-клиент Tauri + локальный API Fastify + PostgreSQL, если право использования подтверждено, блокирующие риски устранены и сборка воспроизводима. Админка – вспомогательная, облако/подписка – позднее. | [Статический аудит P0](P0_SOURCE_AUDIT_2026-11-11.md); при отсутствии прав или невыгодном исправлении – независимый собственный однопользовательский прототип. Реальный запуск не проверен. |
| D-017 | **БЛОКЕР до эксплуатации соответствующих возможностей** | Не активировать файловую запись агента, старый механизм запуска обновлений, отключённую проверку TLS и доступ извне до исправлений/тестов. | [Риски S-01–S-06](P0_SOURCE_AUDIT_2026-11-11.md#3-приоритетные-риски-безопасности). |

| D-018 | **ИССЛЕДОВАНО, ОКОНЧАТЕЛЬНО НЕ УТВЕРЖДЕНО** | Варианты основы: A – существующий Tauri/Fastify/PostgreSQL, B – LibreChat (MIT), C – AnythingLLM (MIT). По манифестам C проще для быстрого личного стенда (1 контейнер), A потенциально сокращает повторную разработку, B имеет более тяжёлый стандартный состав (6 сервисов). | [Сравнение P0](P0_COMPARATIVE_EXPERIMENT_2026-11-11.md): статические тесты A пройдены частично, динамические тесты A/B/C пока не выполнены. **Не менять архитектуру до испытания [Issue №2](https://github.com/Ren472230/RenAIHUB/issues/2).** |

## Как вносить новые решения

1. Ссылаться на проблему, альтернативы, технический/коммерческий компромисс и решение владельца.
2. Отмечать статус: **УТВЕРЖДЕНО**, **РАБОЧЕЕ ОГРАНИЧЕНИЕ**, **РЕКОМЕНДОВАНО**, **ГИПОТЕЗА**, **ОТКРЫТО**, **ОТМЕНЕНО**.
3. При утверждении архитектуры или новой возможности обновлять [PRODUCT_SPEC.md](PRODUCT_SPEC.md) и [ROADMAP.md](ROADMAP.md) без создания конкурирующих версий требований.
4. Не объявлять рекомендации или гипотезы одобренными, пока такого решения нет.
